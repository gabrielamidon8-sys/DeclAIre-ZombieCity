# Zombie City

A top-down zombie survival shooter for phones, PCs and controllers. You hold the streets against waves of mutating zombies, chain kills for bigger rewards, and fight bosses that evolve mid-fight. Tune the in-game radio to FM 66.6 for seven channels of music, and the city lights up in time with it.

## Play

- **Windows:** download `ZombieCity-Setup.exe` from the [Releases](../../releases) page and double-click it. It installs the Zombie City Launcher for your Windows account (no administrator password), adds it to the Start menu, offers a desktop shortcut and can start the game straight away; it also shows up in Settings > Apps for uninstalling (your saves are kept). The launcher is a borderless window with the news, your account, a check for updates and Play, which opens the game in its own window (full screen or windowed, your choice). It keeps the game up to date from this repository's releases and hosts Wi-Fi co-op games. Windows may warn that the app is new: choose "More info", then "Run anyway". The first time you host, allow Zombie City on private networks. Prefer nothing installed? `ZombieCity-Launcher-Windows.zip` is the same launcher: unzip it anywhere and run `Zombie City Launcher.exe`.
- **Android:** download the latest `.apk` from the [Releases](../../releases) page and open it on your phone. Updates install over the old version and keep your saves.
- **Browser (Mac, Linux, iPhone, Chromebook and everything else):** play at [gabrielamidon8-sys.github.io/DeclAIre-ZombieCity](https://gabrielamidon8-sys.github.io/DeclAIre-ZombieCity/), or open `zombie-city-offline.html` in any modern browser. It's a single self-contained file that needs no internet connection.

Website: [declairestudios.wordpress.com](https://declairestudios.wordpress.com)

Every version is the same game. It works out what you are playing with (touch screen, keyboard and mouse, or a controller) and switches on the fly; on PC and controller you aim yourself, and every key and button can be changed in Settings > Controls.

## Wi-Fi co-op

Two to four players on the same Wi-Fi play one run together. A PC running the launcher hosts: on the main menu choose **Wi-Fi co-op**, then **Start hosting**. Phones (the Android app) and other PCs on the same network choose Wi-Fi co-op too, and the host's game shows up in their list (or they type the address the host sees). When everyone is in, the host presses **Start the run**.

Everyone fights the same zombies, waves and bosses in the same city, and shares the score. When a player goes down, a teammate stands next to them for a couple of seconds to revive them; everyone is back on their feet when a wave is cleared, and the run ends only when the whole team is down. Everyone sees the host's wave clock, its red last five seconds and the breather. After each wave every player picks a card (while 2.0 is built the card round is replaced by a short breather for the whole team). The A-10 is the team's: anyone can call it in. The web page can't join (browsers don't let a secure page connect to devices on your network), but the apps can.

- **Card rounds never freeze.** Each round has a number, the host sends the cards again until every player has them, and a 30-second timer picks a card for anyone who is away (in the pause menu, on another app, or disconnected). The waiting line shows who has picked.
- **Ping.** The lobby shows every player's ping live. In a run it sits on the HUD; switch it off in the pause menu or in Settings > Gameplay > Wi-Fi co-op.
- **Find your team.** When a teammate is off screen an arrow on the edge of the screen points to them, with their name and distance. Press G (LB on a controller, the pin button on a phone) to drop a marker for everyone.
- **Smooth on a shaky link.** A teammate's game learns how often the host's snapshots really arrive and how much that wobbles, draws each zombie and teammate a little ahead along the way it was moving (by about one snapshot, never more than 0.16 s) and follows more softly when the link is jittery. The host still decides every position, hit and kill; what was learned about the network is kept for next time.
- **Drops are survivable.** If the Wi-Fi blips, the game reconnects by itself for 25 seconds and puts you back in the same slot of the same run; the host keeps your place for 30 seconds. Everyone must run the same version, and an older copy is told to update.
- **What is local and what is shared.** Each device builds the city itself from the run's seed (streets, rivers, weather, props), so the world never travels over the network. Your own movement, aiming and shots run on your device for instant response. The host owns everything that must agree: zombies and bosses, the wave, the score, the cards and revives, and sends a compact snapshot 15 times a second. Late snapshots are dropped rather than queued, so a slow device catches up instead of falling behind.

## Accounts and cloud saves

A free DeclAIre Studios account keeps your progress on every device. Make one on the [account page](https://headless-iilujwebfcb-gabrielamidon8-140e.wix-site-host.com/), then log in from **Account** on the game's main menu (browser, Android app or Windows launcher). After every run the game merges this device's progress with the cloud: unlocks from every device add up, bests are kept, and each device keeps its own totals.

- Accounts run on Wix (members and a data collection). Passwords are never stored by the game; Wix stores only a one-way hash.
- Saves and scores wait for the internet: a cloud save or a board score that cannot get through is kept and sent by itself (after 30 seconds, then 1, 2 and 5 minutes, and straight away when the device is back online). A score left over from last month's season is dropped.
- Each account's save is encrypted on the device with AES-GCM under a random 256-bit key made for that account. That key is wrapped with a key derived from the password (PBKDF2-SHA256, 600,000 rounds, a random salt per account) before it is uploaded, so the stored save can't be read without the password. Changing the password re-wraps the key; after a password reset the game asks once for the old password, or starts a new cloud save from the device's progress.
- One season leaderboard for every platform: your best run each month goes up under your account name.
- Names (survivor, board and co-op) go through a filter for slurs, swearing, threats and personal details (emails, phone numbers, links), with 50 different remarks for anyone trying to sneak something past it. Names that pose as the studio (ADMIN, DECLAIRE, moderator, official and so on, in any spelling such as D3CLA1RE) are saved for the team.
- The studio's admin account shows as **ADMIN|DECLAIRE** (ADMIN in cracked red, DECLAIRE underlined in orange). Only that account can use it: on the board the game checks the row's Wix owner, and in co-op teammates ask Wix to confirm it, so a copy shows as an ordinary name.
- If someone else logs in on your device, your progress is put away and comes back when you log in again; their progress never mixes with yours.

## What's in the game

- Zombie City 2.0 is rebuilding all 1,000 zombies from the ground up. The first 50 are in: each its own person from before (an office worker, a night jogger, a riot cop, a bride, an astronaut, a lineman still crackling with current), with its own build, clothes, headgear and what it carries, its own behaviour beyond health (sprinting in bursts, pouncing, charging, throwing, spitting, screaming the horde on, healing the others, shedding crawlers, a riot shield that stops rounds from the front), and 50 animations of its own. The old mutations and the bosses are switched off until the rest are rebuilt
- 250 weapons that hit like real ones: real muzzle velocities and bullet energy, head shots that all but always kill, body shots that usually do, limbs that cripple, rounds that pass through one zombie into the next
- Wave timers: every wave runs against a clock (about 44 seconds for wave 1, more for each wave after, up to 2½ minutes; Settings > Gameplay > Wave timer: Short, Normal, Long or Off). When it runs out the next wave starts on the spot, on top of whatever is left, with no screen in between. Clear the street first and you get 7 seconds to walk around and a bonus of 10 points for every second left. The last 5 seconds of either clock glow red (the clock, and the edge of the screen) and tick out loud
- A new HUD on every device: glass plates with cut corners, a segmented health bar with a ghost of the damage just taken, the wave clock in the middle with the zombies still to come, the weapon in its rarity's colour, a ticked dash ring, and a touch joystick that lights the way you push. On narrow phones the A-10 sits above the dash and a bigger HUD size grows only a little
- A command-deck main menu (a status bar with the version, the engines, the wave timer, the network and the time; the run as one big tile; everything else as tiles with what is behind them), a pause screen with the clock, eight of the run's numbers (accuracy and head shots among them) and three tabs (your build, this wave's threats, a map of the streets around you), and a run-over screen with the new numbers
- The engine room (Settings > Accessibility > Ultra advanced, behind a red warning): every engine's live cost, share of the frame, a minute of history, its level, health and its own numbers, how intricate it is (lines, functions, parts and links), and two controls each: how hard it runs (Auto, Eco, Normal, Hard, Max) and what it runs on (CPU, GPU, Auto). What an engine cannot do shows Auto-lock in purple with the reason, and a choice that hurts the game (well under the frame-rate target for 8 seconds, or failing again and again) is put back on Auto by the ecosystem for 5 minutes, with the numbers Each card also shows the engine's traits (adapts, repairs itself, learns, covers, heartbeat, self-test, compatible), what it has learned on this device, how far the ecosystem trusts it, its self-test, whether this device gives it what it needs, and who it is (About); Forget wipes what the engines learned
- 27 engines that work as one learning ecosystem (CORE v3, see [ENGINES.md](ENGINES.md) for every engine's character and capabilities). On each device the hub learns what every engine costs at each level and load, so it steps down the engine that saves the most, climbs engines back only when the next level fits, and steps the crowd down before a horde arrives instead of after the frame stutters; it remembers which fix cleared which problem and tries that first next time, trusts engines that run clean (and starts shaky ones a step lighter), restarts an engine that goes quiet, and runs self-tests at start. Engines learn their own lessons too: how jittery the co-op link is (a teammate's screen smooths over it), how fast the radio renders (it keeps more music ready on slow devices), when a phone starts to run hot (the governor eases off just before), how long a city block takes to draw (streaming only builds what fits the frame), how often the sound falls behind (it settles on a quality the device keeps up with), how often the graphics chip loses its context (Auto stays on the processor for a while). Learning never changes the rules of a run, only how the work is done and drawn
- Forbidden cards from the skull at x100 and a prize wheel at x200 and up (the card round between waves is switched off while 2.0 is built)
- An A-10 Warthog airstrike earned at chain 75, with splash-damage rounds that chew up the road
- 25 dashes with their own effects and passives
- FM 66.6, an in-game radio with 7 channels and 35 songs on each (synthwave, heavy metal, industrial, orchestral, lo-fi, drum & bass, chiptune), all generated by the game. Songs end and the next one fades in. Bluetooth plays your own songs
- An endless city made from a seed, different every run: downtown, burning districts, riot zones, destroyed blocks, ash towns, suburbs, deserts and the frozen north, each district with its own name. Plazas are gardens, squares, street markets or basketball courts; rooftops have water towers, ducts, stair hatches, solar panels and gardens; streets have crossings, manholes, drains, hydrants, traffic lights, bus stops and power lines; suburban houses have driveways, pools and sheds; the desert has ranches, trailers, shacks and windmills; the north has hamlets along ploughed lanes and ski lodges; and districts blend into each other at the edges
- Rivers with bridges (wading slows you down), ponds, frozen rivers and dry washes
- Real-world scale (Settings > Gameplay > World scale): 32 units to the metre, so roads are about 8 m across, cars 4 to 5 m long and a person about half a metre wide. Big mutants are 1 to 2 m wide and bosses 3 to 5 m, and bosses walk straight through cars, fences and benches (setting off the car alarms). Classic keeps the old compact city
- LUX, the game's own lighting engine: every street lamp, lit window, fire, muzzle flash, explosion, lightning strike and your flashlight casts rays, so buildings, cars and zombies throw real shadows, with bloom and glow on top. Every lamp has a height: walls taller than it block its light, while cars, wrecks, trees, bushes, zombies and players throw shadows away from it that end where they should, and the light falls off from the lamp head the way a real one does. Flashlight and headlight beams show as shafts in rain, fog and dust. The sun moves across the sky with the hour and the season and casts long shadows from buildings (by height), trees, zombies and players; it is an area light, so a shadow is sharp at its foot and softens and fades towards its tip; light also bounces: a path tracer sends rays through the city to work out global illumination (lamp light spilling off walls onto the street) and how much sky each spot can see (ambient occlusion). It runs on the graphics card when there is one and on the processor when there isn't, so lights trace on every device. A day and night cycle (dawn, noon, golden dusk, night, or a fixed time or your real clock in Settings), wet streets that shine and fog that glows round the lamps. It measures its own cost, steps its detail down and back up to keep the frame rate, rebuilds its canvases when they are lost, and switches itself off for a minute if it keeps failing
- PRISM, the game's own shader engine: the finished frame goes through the graphics card (WebGL 2, or WebGL 1 on older devices) for bloom, light shafts from the sun and lamps through fog and dust, heat haze, sharpening, a clean upscale, chromatic aberration, exposure, white balance by color temperature (warm dusk, cool night, gray rain, with a Warm, Neutral or Cool setting), saturation, contrast, split toning, vignette and film grain. Without a graphics card it does the same grade on the processor. It repairs itself: a lost graphics context, a shader that won't compile or a slow card sends it to the processor and it comes back when it can
- TEXEL, the game's own texture and resolution engine: the street's surfaces (aggregate in the asphalt, poured concrete, grass, sand ripples, drifted snow, wear and dirt) and caustics in the water; every zombie sprite gets skin, cloth and grime textures and a rim, drawn at up to twice the resolution and scaled down for sharp edges, and the player is drawn from cached, textured sprites instead of a jointed rig. It picks its resolution from the device, steps down when memory or frame time runs short, and rebuilds what it loses
- CORE, the engine hub: all 27 of the game's engines register with it and share one frame (where the sun and the brightest lights are, the camera, the hot spots), one time budget, a message bus and a watchdog. Engines talk through events (a new run, memory running short, a quality change, a kill, an engine going down or coming back), check themselves, repair themselves, help repair each other (the governor frees memory, the loader warms the lighting again) and cover for each other (the lighting engine does bloom on the processor when the shader engine is down; the game draws plain stains and tracers if the blood or bullet engine is). An engine that keeps failing rests for a while and the ones that depend on it adapt. Each engine's level is remembered on the device with the game's and the engine's version, so it starts where it was steady and recalibrates after an update. Settings > System > Engines lists every engine with what it is doing, its health, its links, its cost and its repairs
- MIRROR, the game's own reflection engine: rivers, ponds, puddles, rain-soaked streets, ice, car glass and paint and fresh blood reflect the sky (by the hour and the weather), the street lamps, fires and headlights, rippled by waves and by rain falling into the puddles, with sun glitter on open water. On the graphics card it is part of the final shader pass; without one it is drawn with blend modes. It steps down by itself (no glitter, no wet streets, then off) when the frame runs late (Settings > Graphics > Reflections)
- GORE, the game's own blood engine: every one of the 40 strains bleeds its own way (classic red, frothing, thick, bile, acid green that glows, radioactive yellow, molten magma that cools to crust, violet void ichor with stars, electric volt blood, spectral ectoplasm that fades fast, teal abyssal ink, mercury, oil, slush, dust and bone), and every gun and mod hits each one differently: holes and exit wounds that stay on zombies that survive, burns and blackening from fire and explosions, frost, electrical scorches on the body and the ground, chunks torn off by big rounds and shotguns up close, bodies blown apart by the launcher, burned to husks by the flamethrower, frozen ones shattering into ice. Sprays fly the way the shot went with a little back-spatter, there are 50 variants each of spray, smear and puddle, bodies shoved by the last hit leave a smear, pieces fly and land, the wounded drip, fresh blood is glossy, rain thins it, it shows bright on snow and clouds in rivers, and walking through it leaves red footprints. Blood fades after its time (Settings > Graphics > Blood lasts) and anything no player can see (in co-op: off every player's screen) is cleared. It measures its own cost, drops details when the frame runs late and rests any part that fails
- TRACER, the game's own bullet engine: every round flies with a white-hot head, a motion-blurred streak and a glow in its gun's style: the machine gun's bright tracer every third round, the sniper's long line with a vapour trail hanging in the air and heat shimmer, shotgun pellet sprays, spinning grenades trailing smoke, flames that burn from white to smoke. Mods colour them and add embers, frost, drips, crackling arcs, curves, sparkles or dark smoke. Bright rounds light the street at night and cast shadows, and rounds hitting concrete puff dust while metal sparks
- AURA, the game's own zombie glow engine: toxic, molten, void, abyssal, electric, radioactive, icy and spectral zombies, burning zombies, bombers and bosses are light sources for the lighting engine, so their glow lights the street and walls and cars cast ray-traced shadows from them; glowing blood lights the ground, a glowing zombie's light goes out in a last flash when it dies, and every zombie's eyes glow at night
- ANIMA, the game's own rig and animation engine: every 2.0 zombie is a jointed body (a pose of 32 numbers, a skeleton in three dimensions seen from above, things higher up drawn a little bigger, so a fall really stretches a body out along the ground) with 50 animations of its own: 10 ways of moving (its own gait: a shamble, a sprint, a march, a waddle, a stomp, a drag, a crawl on its hands, a scuttle on all fours, a bound), 8 idles (one of them a habit from its old life: the office worker on the phone, the cook chopping at nothing, the clown juggling, the lineman jolting with current), 10 attacks (claw swipes, bites, grabs, lunges, slams, headbutts, shoves, combos and one with what it carries: a cleaver chop, a shield bash, a hook slash), 8 hit reactions (head, body front and back, each arm and leg, a stagger), 8 deaths (a head shot, falling forward or back, a spin, dropping to its knees, collapsing, blown off its feet, falling sideways) and 6 specials (rising, an ability's tell and its move, recovering, a roar, getting back up). Transitions cross-fade with the walk kept in step, attacks play on the upper body while the legs keep walking, hits are layered on top, deaths start from whatever pose it was in, and the dead stay where they fell for a while (Settings > Graphics > Bodies stay). The nearest zombies are drawn joint by joint and lit by the lamp or sun beside them; the crowd from cached frames of its walk. The specimen log plays any of a zombie's 50 animations
- BALLISTICS, the game's own gun and bullet physics: each gun fires its real round (a 9 mm pistol about 520 joules, a .357 revolver about 990, a 5.56 mm rifle about 1,770, a 7.62 mm sniper rifle about 3,500, each buckshot pellet about 280) at its real speed, with drag; rounds are swept rays that stop at the first wall, ricochet off glancing ones and pass through car bodies a little slower. On the 2.0 zombies a round lands on the head, body, an arm or a leg (a critical is a head shot; near the edge, an arm): a head shot all but always kills (a helmet can turn a light round), a body shot kills about three times in four with a pistol and nearly always with a rifle (soft armour stops pistol rounds, plates stop rifle rounds, a riot shield stops what comes at its front, a brute shrugs some off), arms and legs rarely kill but cripple (a shot leg limps, two crawl, a shot arm hits weaker, a heavy round or a brittle body takes the arm off), and a round that passes through keeps the energy the body did not take. Recoil kicks the spread with each shot, wider on the move
- SWARM, the game's own crowd engine: from wave 3 the trickle of zombies is joined by packs, hordes and droves of a hundred or more, mostly of one kind, that gather out of sight on one side (announced with the direction and the sound of them coming), march together at one pace and surge when they see you. Zombies heading the same way fall in step and move up to a third faster together, and bodies push each other aside by weight. Crowds push vehicles: every vehicle has a real weight and grip, each zombie pushes with about 220 newtons (more if it is bigger) and the zombies pressed up behind push through it, so a parked sedan takes about 50 zombies to shove sideways (30 lengthwise), an SUV about 70, a city bus about 360 and a semi about 460; burned-out wrecks go easier, explosions shove them too, and moved vehicles stay put, in co-op as well. A horde only puts its shoulder to a vehicle when it stands between the horde and you and you are at it (within about 9 m); anywhere else it goes round. Close in, a horde fans out to surround you instead of queueing up, and gunfire carries: a marching horde within earshot (60 m for a pistol, 90 for a rifle, 120 for a sniper rifle) turns and surges toward the shot. 500 and more zombies can be on screen at once (up to about 840 on fast devices, more in co-op), with levels of detail: off screen they think less often, and on screen the nearest get their full picture while the rest are drawn from small cropped ones in a single pass. Horde size, crowd pushing and crowd detail are in Settings
- MUZZLE, the game's own muzzle flash engine: a different fire for every gun (a pistol's three-pointed star, a revolver's fireball with flame from the cylinder gap, an SMG's quick flicker, the rifles' flash-hider fan, the shotgun's bloom of sparks, the sniper's brake jets and dust kick, the machine gun's shifting flame, the launcher's back-blast, the flamethrower's pilot light), tinted by the gun's modification, with sparks, drifting smoke and ejected brass and shotgun shells that bounce and lie in the street. Every flash lights the street and casts shadows, and your teammates' look the same
- GARAGE, the vehicle engine: 22 kinds of vehicle (sedans, hatchbacks, coupes, SUVs, pickups, vans, taxis, police cars, ambulances, fire trucks, buses, box trucks, semis and more) with liveries, burned-out and rolled wrecks, headlights that still work and cast beams, hazard lights and light bars, and glass that reflects
- SKYWAY, the highway engine: elevated highways on concrete piers cross every district, with spaghetti interchanges of loops and flyovers, abandoned traffic and collapsed spans; the decks throw shadows and fade when you walk underneath. Rarely, an airliner has come down across a block, and light planes and helicopters lie wrecked in the streets
- Close-up detail at real scale: asphalt grain, wheel ruts and oil down the lanes, patched and tar-sealed cracks, concrete gutters, lane arrows, sidewalk slabs with gum and utility covers, roof drains, vent pipes, dishes, masts, gutters and solar panels, and litter in the streets
- Weather and seasons: rain, thunderstorms with lightning strikes, fog, snow, blizzards, sandstorms and ashfall; spring, summer, fall and winter. Leaves pile in the gutters in fall, blossom drifts on the sidewalks in spring, winter roads are plowed with slushy tyre tracks, fireflies come out on summer nights, your breath shows in the cold, rain rings spread in the puddles and cloud shadows sail over the city on a fair day
- Wind: a breeze on a calm day, stronger in rain, a gale in storms. Its direction wanders and gusts roll across the city as waves you can watch moving through the trees and grass. Trees and bushes lean and sway, flames and smoke bend downwind, and paper, plastic bags, leaves, tumbleweeds, snow and ash skitter along the ground. The HUD shows the wind with an arrow
- Ambience: a breeze that swells with each gust and whistles between buildings when it picks up, the low drone of the city, crickets and cicadas, and far-off sounds that fit each district: sirens, horns, helicopters and gunfire downtown; dogs, birdsong, wind chimes and frogs in the suburbs; crows, groaning steel and a church bell in the ruins; creaks and collapses where it burns; coyotes, hawks and rattlesnakes in the desert; wolves and cracking ice up north
- Things to touch: bushes and grass that shake, trees, traffic cones and trash cans to kick, explosive barrels, car alarms that lure zombies, birds that take off, footprints in snow and sand
- Layered gun sounds for every weapon, with shell casings and echoes that change with the district
- A light show that reacts to the radio or your own music (paused while 2.0 is built)
- Settings with a simple Basic page and an Advanced page for graphics, sound (master, music, effects, gunfire, ambience and menu volume), gameplay, controls, accessibility and the system
- Touch, keyboard and mouse, and controllers (Xbox, PlayStation, Switch and others), picked automatically from what you last used. Mouse aim with a crosshair, twin-stick aiming on a controller, optional aim assist or auto-aim, full key and button rebinding, controller rumble and menus you can drive with a controller
- Your name on the main menu, at the top left during a run and on the leaderboard, with the device each score was played on
- Wi-Fi co-op for 2 to 4 players: a PC hosts, phones and other PCs on the same Wi-Fi join, with revives, shared cards and a shared A-10
- Free accounts with encrypted cloud saves across devices, one global season board, and a name filter
- Loading screens with tips that show what is being prepared (starting the game, going into a run, joining co-op) and a warm-up before you play: the streets, the trees, the zombie sprites, the lighting engine and a few real frames are prepared first, so the first seconds never stutter
- Tunes itself to your device: it detects the hardware, adjusts resolution, weather and world detail as you play, and cleans up its own caches

## Building from source

The game is plain JavaScript split into modules that `build.js` joins into one page. They all share one script, so `build.js` stops if two modules define a function with the same name (one would silently replace the other):

```sh
node build.js          # browser version -> zombie-city.html (+ zombie-city-offline.html)
node build.js app      # Android page    -> android/www/index.html
node build.js win      # Windows launcher -> desktop/app/ (launcher.html, game/index.html, game/game.json)
```

To build the Windows launcher, download Electron's Windows x64 zip (`electron-v33.2.1-win32-x64.zip` from Electron's GitHub releases) and run:

```sh
python3 desktop/build_win.py electron-v33.2.1-win32-x64.zip out 1.9.925
ZC_NSIS=/path/to/nsis python3 desktop/build_setup.py out/ZombieCity-Launcher-Windows.zip out 1.9.925
```

The first writes `out/ZombieCity-Launcher-Windows.zip` plus `zombie-city-game.html` and `game.json`; the second turns the zip into `out/ZombieCity-Setup.exe` with [NSIS](https://nsis.sourceforge.io/) 3 (`makensis` on Windows or Linux; `ZC_NSIS` is the folder that holds NSIS's `Include`, `Contrib` and `Stubs`). To ship a game update to everyone who has the launcher, attach those two files (with exactly those names) to a new release on this repository; the launcher reads the newest release that has them, checks the download against the checksum in `game.json` and installs it. The repository has to be public for the launcher to see its releases.

To build the Android app you also need `aapt2`, `android.jar` (API 34), `dx.jar` and Python's `cryptography` package:

```sh
cd android
javac --release 8 -cp android.jar -d build/classes src/com/zombiecity/app/MainActivity.java   # the Wi-Fi co-op scanner and connection live in it too
java -jar dx.jar --dex --output=build/classes.dex build/classes
ZC_KEY=/path/to/zombie-city-signing-key.p12 ZC_KEY_PASS=... python3 build_apk.py
```

The signing key is kept out of this repository on purpose. Every update must be signed with the same key, or phones will refuse to install it over the old version, so keep your copy backed up somewhere safe.

## Adding an engine

Engines are built to be added. A new engine is one more file in the `MODULES` list in `build.js` and one `coreDefine({...})` call inside it:

```js
coreDefine({ name: 'ECHO', kind: 'audio', ver: 1, does: 'One line on what it does.', provides: ['echoes'], needs: ['SFX'],
  feats: { need: ['audio'], without: 'what happens on a device without it' },
  lv: () => ECHO.level, adaptGet: () => ECHO.adapt, loadNow: () => ECHO.voices, loadName: 'voices',   // levels and load: CORE learns what each costs
  trim: () => { ... }, boost: () => { ... }, canTrim: () => ECHO.adapt > -2,                         // how CORE steps it down and back up
  alive: () => G.mode === 'play', check: () => '', repair: () => { }, reset: () => { }, selfTest: () => ({ ok: true, n: 1, pass: 1 }),
  learned: () => ['What it has learned, in a sentence for the engine room.'],
  spec: { files: ['echo'], parts: ['...'], hard: 'what Hard does', eco: 'what Eco does', stats: () => [['Voices', ECHO.voices]] },
  docs: { title: 'The ...', character: '...', does: '...', adapts: '...', repairs: '...', learns: '...', works: '...', runs: '...', tune: '...' } });
```

From that one call the hub links it, budgets it, watches it (heartbeat, checks, learned repairs, self-test), learns its costs on each device, lists its capabilities; the engine room gives it a card with its traits, lessons and controls; the contract test (every engine documented, self-repairing, declaring what it needs and provides) covers it; "how intricate is it" counts its file; and `node tools/engdocs.js > ENGINES.md` writes it into the engines document. Engine rules: learning may change how work is done and drawn, never the rules of a run, and everything an engine does must be guarded so it can never stop the game.

## Releasing an update

Every update goes through three phases, so problems show up before players see them:

1. **Dev.** Build everything (`node build.js`, `node build.js app`, `node build.js win`, the APK and the installer) and run the tests.
2. **Test.** `python3 tools/release.py test` puts the new web version in `test/` (so [the test page](https://gabrielamidon8-sys.github.io/DeclAIre-ZombieCity/test/) gets it) while the main page keeps the published version. Commit and push, then make a GitHub release for the version with **Set as a pre-release** ticked and the five files attached (`ZombieCity-Setup.exe`, `ZombieCity-Launcher-Windows.zip`, `ZombieCity-Android.apk`, `zombie-city-game.html`, `game.json`). Only the admin's launcher sees pre-releases (its Test channel switch); players don't. Set **test** in the Game Status collection on Wix to the version, and the game shows "Test build". Anything wrong is fixed and tested again.
3. **Publish.** Turn on maintenance (Game Status: **maintenance** on, a **message** and an **until** time): players see "Down for maintenance" (a run in progress finishes first) while the admin can still play. Testers without the admin account can get past it too: **Tester code** on the maintenance screen takes the studio's tester code (only its PBKDF2 hash is in the game; a **testerHash** field in Game Status replaces it), and Settings > System > Tester mode leaves. Run `python3 tools/release.py publish`, commit and push, then edit the GitHub release: untick pre-release and tick **Set as the latest release**. Set **stable** to the version (and **minVer** too when older versions can't play with it, such as a co-op change, so they are asked to update). Turn maintenance off.

Game Status is the one-row collection on the DeclAIre Studios Wix project (Wix dashboard > CMS > Game Status). Everyone can read it, only the site's admins can change it, and the game checks it every few minutes.
